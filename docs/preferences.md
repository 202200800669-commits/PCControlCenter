# 配置生命周期

Core 的 `PreferenceStore` 提供 `Create`、`Read`、`Update` 与 `Restore`，供后续界面调用。当前只保存托盘偏好与刷新间隔，CLI 探测频率尚未绑定这些偏好。

`Read` 返回配置与 SHA256 修订标识。`Update` 必须提交上次读取的修订标识；如果文件已变化，则返回冲突，调用方应重新读取。配合稳定的 `.lock` 文件，遵守该协议的多个进程不会相互覆盖。不能把这套协作锁理解为能阻止外部编辑器修改文件。

保存先在同目录写入临时文件并刷新到磁盘，再通过 `File.Replace` 替换。每次更新生成唯一名称的旧版本备份；不自动删除用户备份。替换失败会清理临时文件并保留异常，调用方不能显示保存成功。

恢复必须显式选择备份并提交当前修订标识。恢复前仍验证格式、版本与范围，同时备份被替换的配置。损坏、重复字段、未知字段、缺少字段、超过 16 KB 或包含硬件目标的配置不能加载；不会静默转换为默认值并覆盖原文件。

这些操作不会启动硬件控制、提权代理或开机任务。文件应存放在用户数据目录，程序源码继续保存在 F 盘。
