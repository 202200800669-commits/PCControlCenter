# 架构

依赖方向为 CLI / 未来 WPF UI → Core ← Providers.Windows。界面不包含品牌协议，所有硬件数据带采样时间和可用性；没有读数时使用 null，不能显示伪造的 0。

`DeviceIdentity` 不包含序列号。`ProviderRegistry` 只在唯一匹配时选择适配器；无匹配或多重匹配使用通用只读提供器。ThinkBook 在读取固件接口前还会重新核对本机身份与风扇范围。华硕和机械革命仅实现品牌发现，后续按平台拆分。

`Controller` 在每次命令前重新读取能力，核对身份、验证级别、写权限、有限数值和边界，并将命令串行化。进入写入后的异常或取消返回 UnknownOutcome，不能声称硬件已恢复。通用数值控制接口仍返回 Unsupported。限时风扇试验通过独立的 FanTrial 类型和显式 UAC 操作进入代理，不混用普通数值设置接口。

已实现一次性只读权限代理：普通 CLI 创建随机名称的本地命名管道，通过 UAC 启动同目录 Broker。管道 DACL 仅允许当前用户并拒绝网络身份；双方使用操作系统返回的进程 ID 核对端点，代理还检查调用方为同目录 pc-control.exe。协议版本 2 只允许固定 read-fans 和 fan-trial 操作，拒绝未知字段、协议版本不符和过大消息；代理重新识别本机型号及风扇范围。fan-trial 仅对参考机开放 5–30 秒的实验会话，拒绝超范围参数。

代理只有一个请求，100 秒代理工作期限，客户端等待上限 100 秒；代理提前退出时客户端停止等待。不存在常驻服务、启动任务或任意命令入口。UAC 对话框的用户响应时间由 Windows 管理，不包含在该工作期限中。当前验证的是同一账户的 UAC 提权，跨账户管理员凭据不支持。签名、安装目录权限审查和独立安全复核尚待公开发行前完成。

未来命令按 RPM、百分比、模式枚举分别建模；当前数值请求只用于验证架构，不覆盖显卡切换、充电模式、配置组合事务。风扇写入需要读回观察、恢复自动及进程异常测试，不能从现有读数推断写入能力。

PowerShell 只读脚本编译在程序集内，无外部脚本路径和用户输入拼接。不改变执行策略。常规系统读取使用 CIM 属性；ThinkBook 风扇仅调用已识别的 GetFeatureValue。普通探测没有 setter；单独嵌入的 FanSession.ps1 才包含三个明确允许的风扇写入编号。没有驱动安装、服务修改和网络上传。


风扇会话使用 Global\PCControlCenter.ThinkBookFanSession 互斥锁避免本项目的会话重叠；不宣称能阻止官方软件或第三方工具争用。独立 PowerShell 工作进程重新验证身份、范围后才写入，自身计时并监听 stdin EOF。CLI 断连时 Broker 关闭工作进程输入，工作进程进入 finally 恢复；Broker 被终止时输入管道 EOF 同样提供停止信号。若工作进程超过 80 秒仍未返回，报告恢复未确认而不直接杀死正在执行恢复的进程。三条恢复写入逐条尝试，不因第一条失败而跳过后续命令。

协议层、客户端与工作进程均检查请求。只从已验证字符串枚举和整数生成内嵌脚本参数；用户不能提供脚本路径。由于独立自动模式状态不可读取，回执严格区分命令发送、开关读回与实际转速，避免把指令发送成功当作恢复状态已获完整证明。
